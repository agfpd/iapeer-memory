# 11 — Конфигурация

**Русский** · [English](../11-configuration.md)

Всё, что настраивается в iapeer-memory, задаётся переменными окружения с префиксом `IAPEER_MEMORY_*`. Постоянное место для них — файл `config.env`; на время сеанса любую переменную можно переопределить через окружение процесса. Из коробки система работает без единой правки (поиск на BM25, режим курирования по умолчанию), поэтому настраивайте только то, что нужно изменить.

## Где лежит конфигурация

Один файл:

```
~/.iapeer/plugins/iapeer-memory/config.env
```

Его создаёт `init` один раз и больше не трогает — файл ваш. Формат — построчный `KEY=VALUE`:

```bash
# Комментарии и пустые строки игнорируются
IAPEER_MEMORY_VAULT_PATH=/Users/you/iapeer-memory-vault
IAPEER_MEMORY_LOCALE=ru
IAPEER_MEMORY_MODE=lean
export IAPEER_MEMORY_MCP_PORT=8766   # префикс export допустим
```

Значение в кавычках (одинарных или двойных) разворачивается на один уровень; экранирование не обрабатывается — это конфиг, не shell.

### Порядок приоритета

```
флаги команды  >  окружение процесса  >  config.env  >  встроенные значения
```

Переменная, уже заданная в окружении, **не** перезаписывается файлом — явный `IAPEER_MEMORY_*=` в окружении всегда побеждает. Это удобно для разовых проверок: запустили команду с переменной в строке вызова — она перебьёт файл, не меняя его.

### Когда изменения вступают в силу

- **Поиск, пути, порт, параметры демона** — `memoryd` читает их при старте. Перезапустите демон, чтобы применить (`notifier` поднимет его заново; либо выполните `iapeer-memory update`).
- **Режим курирования и роли** — триггеры `notifier` (наблюдатель и таймер консолидации) регистрируются под текущий режим командами `init` / `verify --repair` / `update`. После правки переменных курирования выполните `iapeer-memory verify --repair` — он переинициализирует триггеры под новый режим; эмиссию такта демон подхватит при следующем перезапуске.

## Vault и язык

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_VAULT_PATH` | — (**обязательна**) | Абсолютный путь к хранилищу. Без неё демон не стартует. Должен быть существующим каталогом — на опечатке или отмонтированном диске система падает сразу, а не работает «вхолостую» на пустом vault. |
| `IAPEER_MEMORY_LOCALE` | `en` | Язык раскладки папок и таксономии: `en` или `ru`. Выбирается при установке, после наполнения vault не меняется на лету. |

## Режим курирования

Это ответ на вопрос «как отключить кураторов и такты». Ключевой принцип: **режим управляет только проактивностью курирования, а не наличием чего-либо**. База — индексация, поиск, архивирование по статусу, дедуп, генерация карты в промпт — работает всегда, в любом режиме. Роли-кураторы (Index, Scriber, DreamWeaver) тоже всегда созданы и доступны по вызову. Режим решает одно: будит ли система кураторов сама.

### Два режима

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_MODE` | `curated`, если переменной нет; новый `init` записывает `lean` | `lean` — база работает, такт курирования молчит (кураторов система сама не будит). `curated` — поверх базы система проактивно поднимает кураторов по такту. |

Тонкость с умолчанием: в коде отсутствующая переменная читается как `curated` (так совместимость со старыми хостами, развёрнутыми до появления режимов). Но `init` на новом хосте **записывает** `IAPEER_MEMORY_MODE=lean` в `config.env` — поэтому свежая установка работает в lean. Повторный `init` существующий режим сохраняет, молча не переключает.

### Переключатели по ролям

Поверх режима каждую роль включают и выключают отдельно:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_PROACTIVE_INDEX` | следует режиму | Проактивность Index (обогащение связей, здоровье). |
| `IAPEER_MEMORY_PROACTIVE_SCRIBER` | следует режиму | Проактивность Scriber (вычитка канона). |
| `IAPEER_MEMORY_PROACTIVE_DREAMWEAVER` | следует режиму | Проактивность DreamWeaver (еженедельная консолидация оперативки). |

Значения: `on` / `1` / `true` / `yes` / `y` — включить; `off` / `0` / `false` / `no` / `n` — выключить; пусто или нераспознанное — следовать режиму. В `curated` все три по умолчанию включены, в `lean` — выключены.

Логика такта: система эмитит `CURATOR_TICK`, только если есть кому его принять — активен Scriber или Index. Если активен Scriber, пачка идёт ему (он вычитывает и передаёт Index); иначе — сразу Index; если оба выключены — такт не эмитится вовсе. DreamWeaver отдельный: его еженедельный таймер регистрируется, только когда роль проактивна.

### Рецепты

**Отключить только DreamWeaver** (Index и Scriber продолжают работать):

```bash
IAPEER_MEMORY_MODE=curated
IAPEER_MEMORY_PROACTIVE_DREAMWEAVER=off
```

Еженедельный таймер консолидации не регистрируется; такт `CURATOR_TICK` для Index/Scriber работает как прежде.

**Полностью заглушить курирование** (только база — индексация, поиск, архивирование):

```bash
IAPEER_MEMORY_MODE=lean
```

Кураторов система сама не будит, такт не эмитится. Vault остаётся свежим: новые заметки индексируются, устаревшие уходят в архив по статусу, дедуп-подсказки и карта в промпт работают. При необходимости любого куратора всё ещё можно вызвать вручную.

**Включить полное курирование:**

```bash
IAPEER_MEMORY_MODE=curated
```

После любой из этих правок выполните `iapeer-memory verify --repair`, чтобы триггеры `notifier` встали под новый режим.

### Кто считается куратором

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_CURATOR_SET` | `index,scriber,dreamweaver` | Список личностей через запятую, чьи правки система считает санкционированным курированием и **не** помечает на ревизию (`needs_review`). |

Когда заметку правит не автор и не куратор, система ставит `needs_review` — заметка попадает в очередь разбора. Правки личностей из этого списка флаг не ставят. Если вы переименовали роли или завели нового куратора, обновите список — иначе правки нового куратора система примет за ручные правки извне и зря пометит заметки на ревизию.

### Период такта

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_CURATOR_TICK_SECS` | `21600` (6 часов) | Период такта `CURATOR_TICK` в секундах. Раз в этот срок накопившиеся правки канона уходят курированию одним списком — пачкой, а не на каждое событие. |

## Расписание консолидации (DreamWeaver)

Еженедельный такт уборки оперативки настраивается отдельно. Все переменные опциональны.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_DREAM_CRON` | `0 4 * * 1` (понедельник, 04:00) | Расписание такта в формате cron (5 полей). |
| `IAPEER_MEMORY_DREAM_WINDOW_DAYS` | `7` | Окно в днях: заметки и транскрипты за этот срок попадают в разбор. |
| `IAPEER_MEMORY_DREAM_DESC_MAXLEN` | `250` | Длина описания (символы), сверх которой заметка — кандидат на переформулировку. |
| `IAPEER_MEMORY_DREAM_BATCH_THRESHOLD` | `20` | Сколько заметок в папке → отдельный субагент на папку; меньше — группируются. |
| `IAPEER_MEMORY_DREAM_GROUP_CAP` | `20` | Потолок суммарного веса сгруппированных папок. |
| `IAPEER_MEMORY_DREAM_TRANSCRIPT_CAP` | `20` | Потолок транскриптов на папку (`0` — без потолка). |

## Поиск

По умолчанию поиск работает на полнотекстовом BM25 — это полноценный режим, без сети и внешних сервисов. Векторный поиск (по смыслу) и переранжирование подключаются опционально: пустой адрес эндпойнта означает, что слой выключен.

### Векторный поиск (эмбеддинги)

Включается заданием адреса эндпойнта. Подходит любой сервис с протоколом OpenAI `/v1/embeddings` или TEI.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_EMBEDDING_ENDPOINT` | пусто (выключено) | Адрес эндпойнта эмбеддингов. Пусто → поиск только на BM25. |
| `IAPEER_MEMORY_EMBEDDING_PROVIDER` | `openai` | Формат протокола: `openai` или `tei`. |
| `IAPEER_MEMORY_EMBEDDING_MODEL` | `Qwen/Qwen3-Embedding-8B` | Имя модели эмбеддингов. |
| `IAPEER_MEMORY_EMBEDDING_DIMENSIONS` | `4096` | Размерность вектора (зависит от модели). |
| `IAPEER_MEMORY_EMBEDDING_BATCH_SIZE` | `32` | Размер пачки запросов к сервису. |
| `IAPEER_MEMORY_EMBEDDING_API_KEY` | пусто | Ключ API, если сервис его требует. |

### Переранжирование (reranker)

Дополнительный слой поверх векторного поиска. Тоже off-by-default.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_RERANKER_ENDPOINT` | пусто (выключено) | Адрес эндпойнта переранжирования (протокол TEI `/rerank` и совместимые). |
| `IAPEER_MEMORY_RERANKER_PROVIDER` | `tei` | Формат: `tei`, `cohere`, `nvidia`, `jina` или `none` (явное выключение даже при заданном адресе). |
| `IAPEER_MEMORY_RERANKER_MODEL` | `BAAI/bge-reranker-v2-m3` | Имя модели переранжирования. |
| `IAPEER_MEMORY_RERANKER_TOP_K` | `20` | Сколько верхних кандидатов отдавать на переранжирование. |
| `IAPEER_MEMORY_RERANKER_WEIGHT` | `0.7` | Вес оценки reranker при смешивании (0–1; остальное — вес полнотекстовой оценки). |
| `IAPEER_MEMORY_RERANKER_API_KEY` | пусто | Ключ API, если сервис его требует. |

Если эндпойнт сконфигурирован, но сервис недоступен, поиск молча деградирует к BM25 — выдача остаётся валидной.

### Тонкая настройка индекса и выдачи

Эти параметры менять обычно не нужно.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_MAX_RESULTS` | `6` | Сколько заметок возвращает `memory_search`. |
| `IAPEER_MEMORY_CHUNK_SIZE` | `500` | Размер чанка при индексации (символы). |
| `IAPEER_MEMORY_CHUNK_OVERLAP` | `80` | Перекрытие соседних чанков (символы). |
| `IAPEER_MEMORY_RRF_K` | `60` | Константа объединения двух слоёв поиска (Reciprocal Rank Fusion). |
| `IAPEER_MEMORY_FULL_SCAN_ON_STARTUP` | `true` | Полный переиндекс vault при старте демона (гарантия консистентности). `false` — быстрее старт, доверяя инкрементальному индексу. |
| `IAPEER_MEMORY_EXCLUDE_FOLDERS` | папка `99_Система` / `99_System` | Папки (через запятую), пропускаемые при индексации. |

Веса статусов в выдаче (актуальные выше, устаревшие ниже), штраф за чужую оперативку, прибавка заметкам-хабам — фиксированы в коде и переменными не настраиваются; их разбирает [06 — Поиск и запись](06-поиск-и-запись.md).

### Подсказки при записи

Когда подключён векторный поиск, после записи заметки система подсказывает близкие — возможный дубль или связь.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_DEDUP_THRESHOLD` | `0.78` | Косинусная близость ≥ порога → подсказка «возможный дубль». |
| `IAPEER_MEMORY_LINK_HINT_THRESHOLD` | `0.68` | Близость в диапазоне `[порог, dedup)` → подсказка «возможно, стоит связать». |

## MCP и владелец

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_MCP_PORT` | `8766` | Порт HTTP-эндпойнта MCP у `memoryd` (сосед фундамента iapeer на 8765). Тот же порт должен быть прописан в поверхностях пиров — меняйте через `verify --repair`, не вручную. `0` — эфемерный порт (для тестов). |
| `IAPEER_MEMORY_HUMAN_NAME` | пусто | Личность владельца-человека. Задана → включается распознавание ручных правок (атрибуция, защита от ложных срабатываний внешнего редактора). Пусто → правки считаются машинными. |
| `IAPEER_MEMORY_AGENT_NAME` | пусто | Запасное имя вызывающего для CLI и программных потребителей вне сессий (в сессии личность приходит из заголовка идентичности и важнее). |

## Прочее (продвинутое)

Тонкие настройки, которые нужны редко.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_MEMORY_FRESH_EDIT_WINDOW_S` | `90` | Окно «свежей» правки в секундах: как долго после записи правка ещё считается своей при распознавании ручных правок извне. |
| `IAPEER_MEMORY_INDEX_AGENT` | `index` | Личность, считающаяся ролью Index при генерации авторских индексов и фрагментов. Меняйте, если переименовали роль Index. |
| `IAPEER_MEMORY_PROJECTS_ROOT` | — (нет) | Запасной корень для определения рабочего каталога проекта в авторских индексах. |
| `IAPEER_MEMORY_TAGS_BOUNDARY_MAXLEN` | `160` | Длина границы тега (символы) в проекции словаря, доставляемой в промпт; держит проекцию компактной. |

## Пути и хранилище

Каждый корень переопределяется отдельно; по умолчанию всё лежит под `IAPEER_ROOT` (сам он по умолчанию `~/.iapeer`).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `IAPEER_ROOT` | `~/.iapeer` | Корень хранения всей экосистемы iapeer. |
| `IAPEER_MEMORY_CONFIG_FILE` | `<IAPEER_ROOT>/plugins/iapeer-memory/config.env` | Путь к самому файлу конфигурации. |
| `IAPEER_MEMORY_STATE_DIR` | `<IAPEER_ROOT>/state/iapeer-memory/` | Состояние: индексы авторов, heartbeat, манифест ролей, хеши. |
| `IAPEER_MEMORY_CACHE_DIR` | `<IAPEER_ROOT>/cache/iapeer-memory/` | Кэш: SQLite-индекс, зеркало словаря тегов. |
| `IAPEER_MEMORY_LOGS_DIR` | `<IAPEER_ROOT>/logs/iapeer-memory/` | Лог-файлы. |
| `IAPEER_MEMORY_DB_PATH` | `<CACHE_DIR>/index.db` | Файл базы SQLite. |
| `IAPEER_MEMORY_BINARY_PATH` | `~/.local/bin/iapeer-memory` | Скомпилированный бинарь CLI (на него ссылаются хуки и наблюдатель). |

## Полный список переменных

Сводка по всему вышесказанному — для быстрого поиска.

**Обязательные:** `IAPEER_MEMORY_VAULT_PATH`.

**Vault и язык:** `IAPEER_MEMORY_LOCALE`.

**Курирование:** `IAPEER_MEMORY_MODE`, `IAPEER_MEMORY_PROACTIVE_INDEX`, `IAPEER_MEMORY_PROACTIVE_SCRIBER`, `IAPEER_MEMORY_PROACTIVE_DREAMWEAVER`, `IAPEER_MEMORY_CURATOR_SET`, `IAPEER_MEMORY_CURATOR_TICK_SECS`.

**Консолидация:** `IAPEER_MEMORY_DREAM_CRON`, `IAPEER_MEMORY_DREAM_WINDOW_DAYS`, `IAPEER_MEMORY_DREAM_DESC_MAXLEN`, `IAPEER_MEMORY_DREAM_BATCH_THRESHOLD`, `IAPEER_MEMORY_DREAM_GROUP_CAP`, `IAPEER_MEMORY_DREAM_TRANSCRIPT_CAP`.

**Поиск:** `IAPEER_MEMORY_EMBEDDING_ENDPOINT`, `IAPEER_MEMORY_EMBEDDING_PROVIDER`, `IAPEER_MEMORY_EMBEDDING_MODEL`, `IAPEER_MEMORY_EMBEDDING_DIMENSIONS`, `IAPEER_MEMORY_EMBEDDING_BATCH_SIZE`, `IAPEER_MEMORY_EMBEDDING_API_KEY`, `IAPEER_MEMORY_RERANKER_ENDPOINT`, `IAPEER_MEMORY_RERANKER_PROVIDER`, `IAPEER_MEMORY_RERANKER_MODEL`, `IAPEER_MEMORY_RERANKER_TOP_K`, `IAPEER_MEMORY_RERANKER_WEIGHT`, `IAPEER_MEMORY_RERANKER_API_KEY`, `IAPEER_MEMORY_MAX_RESULTS`, `IAPEER_MEMORY_CHUNK_SIZE`, `IAPEER_MEMORY_CHUNK_OVERLAP`, `IAPEER_MEMORY_RRF_K`, `IAPEER_MEMORY_FULL_SCAN_ON_STARTUP`, `IAPEER_MEMORY_EXCLUDE_FOLDERS`, `IAPEER_MEMORY_DEDUP_THRESHOLD`, `IAPEER_MEMORY_LINK_HINT_THRESHOLD`.
