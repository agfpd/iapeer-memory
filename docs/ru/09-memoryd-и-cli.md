# 09 — memoryd и CLI

**Русский** · [English](../09-memoryd-and-cli.md)

## memoryd

`memoryd` — единственный постоянный процесс iapeer-memory и единоличный владелец базы. Через него проходит всё, что требует индекса или поиска. Он:

- **индексирует vault** — полный проход при старте, дальше инкрементально по изменениям файлов (с защитой от лишних пересборок: переиндексируется только то, что реально изменилось по содержанию);
- **отвечает на поиск** — держит MCP-эндпойнт по HTTP на локальном порту (по умолчанию 8766) с инструментами `memory_search` / `memory_related` / `memory_map`;
- **замечает изменения** и сообщает о них курированию;
- **генерирует карту памяти** агента в слой системного промпта (per-peer фрагменты: блок путей, проекция тегов, индекс автора; общий гайд пишут `init`/`update`, не демон);
- **держит heartbeat** — файл, по свежести которого проверяют, жив ли демон.

База — SQLite в `~/.iapeer/cache/iapeer-memory/index.db` (полнотекстовый индекс плюс граф связей; при подключённом векторном поиске — ещё и эмбеддинги). Конфигурация — один файл `~/.iapeer/plugins/iapeer-memory/config.env` (путь к vault, язык, имя владельца, порт, адреса поиска); его правит владелец, пакет не перезаписывает. Полный список переменных — в [11 — Конфигурация](11-конфигурация.md).

Демон работает под наблюдением `notifier` — тот перезапускает его при падении и замечает зависание по heartbeat. Сам `memoryd` не маршрутизирует сообщения и не будит агентов — это делает iapeer; memoryd только индексирует, ищет и сигналит об изменениях.

## CLI iapeer-memory

Команды для оператора:

| Команда | Что делает |
|---|---|
| `init` | Развернуть систему: vault, конфиг, бинарь, кураторов, демон, слот памяти. Идемпотентно. |
| `status` | Снимок всей цепочки: конфиг, демон, слот, поиск. Ненулевой код — что-то требует внимания. |
| `verify [--repair]` | Быстрая самопроверка живых поверхностей (vault, heartbeat, регистрация демона, доктрины кураторов). `--repair` чинит автоматически исправимое. |
| `update [--skip-binary]` | Обновить всё одной командой: бинарь, шаблоны, доктрины, слот, триггеры, перезапуск демона. Идемпотентно. |
| `migrate --source <папка> --agent <имя> [--apply]` | Перенести встроенную память рантайма указанного агента в его оперативку vault. По умолчанию пробный прогон; `--apply` — реальный перенос. Имя агента обязательно (флаг `--agent` или переменная `PEER_PERSONALITY`). |
| `uninstall [--keep-binary]` | Снять систему: слот, бинарь, триггеры, регистрацию. Vault и конфиг остаются. |
| `archive-stale [--commit]` | Перенести в архив накопившиеся заметки с финальным статусом (memoryd архивирует новые по ходу, эта команда разгребает старый хвост). По умолчанию пробный прогон; `--commit` — реальный перенос. |
| `version` · `help` | Версия пакета · справка. |

Команду `provision-peer --cwd <папка> --runtime claude|codex --personality <имя>` обычно вызывает ядро iapeer при рождении пира, но её же запускают вручную, чтобы подключить память конкретному существующему пиру (см. [02 — Быстрый старт](02-быстрый-старт.md)). Ещё две команды чинят атрибуцию заметок и иногда нужны автору вручную: `bake` переставляет «кто менял» на заметках, записанных в обход хука (через bash), а `fm-update` правит служебные поля точечно. Остальное (`unprovision-peer`, `memoryd`, `hook`, `render`, `dream-collect`, `install-binary`) вызывает не оператор, а сама система и ядро iapeer — при рождении и удалении пиров, запуске демона под `notifier`, событиях файловой системы и тиках консолидации.
