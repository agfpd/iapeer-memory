# 01 — Обзор

**Русский** · [English](../01-overview.md)

iapeer-memory даёт команде агентов общую долговременную память. Один агент записывает знание — вся команда находит его поиском; запись переживает перезапуск сессии и сжатие контекста. Это эталонный провайдер слота памяти [iapeer](https://github.com/agfpd/iapeer).

## Две части памяти

**Канон** — общее знание команды, ценное для всех и надолго. Делится на пять жанров: знания, решения, идеи, проекты, списки ([04 — Жанры заметок](04-жанры-заметок.md)). В канон материал попадает напрямую: автор (агент или человек) пишет сразу в нужную типизированную папку — папка объявляет жанр, хук записи заполняет служебные поля при записи. Курирование подключается потом — вычитка и обогащение связей уже размещённой заметки.

**Оперативка** — личные заметки агента: обратная связь от владельца, рабочий контекст, профиль человека, грабли после инцидента. У каждого агента своя зона, писать в неё может только он; читать — вся команда (чужая оперативка в поиске идёт с пониженным весом). Оперативка заменяет встроенную память рантайма — она у Claude и Codex отключается, чтобы не было второго неуправляемого хранилища.

## Понятия

**Vault** — хранилище: каталог markdown-файлов, совместимый с Obsidian. Восемь папок верхнего уровня, набор фиксированный, имена настраиваются (есть русская и английская раскладка). Раскладку разбирает [03 — Vault: раскладка и зоны](03-vault-и-зоны.md).

**Заметка** — отдельный markdown-файл с frontmatter (служебные поля: тип, статус, автор, дата) и телом. Тип заметки определяется папкой; служебные поля проставляет система, не агент.

**Связи** — заметки ссылаются друг на друга вики-ссылками `[[Имя]]`, образуя граф. По графу память навигируется; курирование обогащает связи уже размещённых заметок. См. [05 — Связи и теги](05-связи-и-теги.md).

## Компоненты

```text
┌─────────────────────────────────────────────────────────────┐
│  Агент: пишет заметки · ищет через MCP-инструменты            │
└───────────────┬─────────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────────┐
│  memoryd — единый демон                                      │
│  • индексирует vault в SQLite                                │
│  • отвечает на memory_search / memory_related / memory_map (MCP)  │
│  • замечает изменения файлов и эмитит события                │
│  • генерирует карту памяти агента в системный промпт         │
└───────────────┬─────────────────────────────────────────────┘
                │ события об изменениях
┌───────────────▼─────────────────────────────────────────────┐
│  Кураторы (эфемерные, по такту): Index · Scriber · DreamWeaver │
│  обогащение связей, вычитка, здоровье хранилища, консолидация │
└──────────────────────────────────────────────────────────────┘
```

**memoryd** — единственный постоянный процесс и владелец базы. Индексирует vault, отвечает на поисковые запросы по MCP, замечает изменения файлов, генерирует карту памяти для системного промпта, держит heartbeat для проверок здоровья. См. [09 — memoryd и CLI](09-memoryd-и-cli.md).

**MCP-инструменты** — то, чем агент работает с памятью: `memory_search` (поиск по смыслу и содержанию), `memory_related` (граф связей вокруг заметки), `memory_map` (топология хранилища). Все только на чтение; запись идёт обычным созданием файла. См. [06 — Поиск и запись](06-поиск-и-запись.md).

**Кураторы** — агенты-роли, поддерживающие порядок: Index, Scriber, DreamWeaver. Все эфемерные: поднимаются по такту `CURATOR_TICK` или по требованию, отрабатывают и сворачиваются — постоянного куратора нет, постоянен только `memoryd`. Index обогащает связи и чинит здоровье хранилища (битые ссылки, дубли). Scriber вычитывает заметки канона (стиль, фактчек). DreamWeaver консолидирует оперативку (еженедельно по таймеру). Размещение заметок — не на кураторах: автор пишет сразу в типизированную папку. См. [08 — Курирование](08-курирование.md).

## Как память доезжает агенту

Два пути, и они дополняют друг друга:

1. **Карта в системном промпте.** При запуске сессии агент получает слоем системного промпта (слой 5 iapeer) две вещи: гайд по работе с памятью и индекс собственных заметок — что у него есть, по каким темам. Карта пересобирается на каждом запуске, поэтому всегда свежая. См. [07 — Доставка в контекст](07-доставка-в-контекст.md).
2. **Поиск во время работы.** Карта — это ориентир «что у меня есть»; за конкретным содержанием агент идёт в `memory_search`, который ищет по всему хранилищу команды, не только по своим заметкам.

## Связь с iapeer

iapeer-memory не самостоятельная система — это примитив поверх [iapeer](https://github.com/agfpd/iapeer). Он занимает слот памяти ядра и опирается на его механизмы: системный промпт (доставка карты), обмен сообщениями (кураторы общаются с авторами), расписания (еженедельная консолидация). Поэтому iapeer и `notifier-runtime` — обязательные зависимости. Точки интеграции разбирает [10 — Интеграция с iapeer](10-интеграция.md).
