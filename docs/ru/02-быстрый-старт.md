# 02 — Быстрый старт

**Русский** · [English](../02-quickstart.md)

От установки до первой заметки и поиска. Под каждым шагом — что он делает.

## Требования

- **macOS** — как и у iapeer.
- **Установленный и работающий [iapeer](https://github.com/agfpd/iapeer)** — память доставляется его системным промптом и опирается на его обмен сообщениями. Без iapeer система не собирается.
- **`notifier-runtime`** — через него работают события (замечать изменения) и расписания (консолидация, таймауты). Тоже обязателен.

## Установка

```bash
npx @agfpd/iapeer-memory init
```

В интерактивном терминале команда спросит: путь к хранилищу (vault), язык раскладки папок (русская или английская), имя владельца и адрес векторного поиска (его можно не задавать — поиск работает на BM25). Адрес переранжирования задаётся флагом `--reranker-endpoint`. Для скриптов те же значения передаются флагами (`--vault`, `--locale`, `--human` и др.); в неинтерактивном режиме без пути к vault команда откажется работать, а не создаст хранилище молча.

Что разворачивает `init`:

- **vault** — структуру папок (по выбранному языку) и системные шаблоны;
- **конфигурацию** `~/.iapeer/plugins/iapeer-memory/config.env` — путь к vault, язык, имя владельца, порт MCP, адреса поиска (вы её потом правите, пакет не перезапишет; все переменные — в [11 — Конфигурация](11-конфигурация.md));
- **бинарь** `~/.local/bin/iapeer-memory`;
- **кураторов** — создаёт агентов-роли (Index для связей и здоровья, Scriber для вычитки канона, DreamWeaver для консолидации) с их доктринами; роли эфемерные, поднимаются по такту;
- **демон** — регистрирует `memoryd` под `notifier` (наблюдатель перезапустит его при падении); таймер еженедельной консолидации регистрируется только в режиме `curated` — свежий `init` пишет дефолтный `lean`, в котором такты курирования не эмитятся (см. [11 — Конфигурация](11-конфигурация.md));
- **слот памяти** — пишет `~/.iapeer/memory-provider.json`, занимая единственный на хост слот;
- **отключает родную память** Claude и Codex (`iapeer native-memory off --all`), чтобы не было второго хранилища;
- **гайд** — кладёт памятку по работе с памятью в общий слой системного промпта.

Установка идемпотентна — повторный запуск безопасен.

## Проверка

```bash
iapeer-memory status     # снимок всей цепочки: vault, демон, слот, поиск
iapeer-memory verify     # быстрая самопроверка живых поверхностей
```

`status` показывает состояние хранилища, свежесть демона, занятость слота и работоспособность поиска; ненулевой код возврата означает, что что-то требует внимания. `verify --repair` чинит то, что чинится автоматически (например перерисовывает доктрины кураторов).

## Память у агентов

Память подключается к пиру не отдельной командой `iapeer-memory`, а через слот ядра iapeer:

- **Новый или онбордящийся пир.** Пир заводится средствами iapeer: `iapeer create <имя>` — создать нового, либо `iapeer init` в папке пира — онбордить существующую папку. Любой из путей проводит пира через provision: ядро видит занятый слот памяти и само вызывает provision-команду провайдера — она кладёт пиру поверхности. Отдельного шага для памяти не нужно. (Не путать с `iapeer-memory init` — это установка самой системы памяти, не создание пира.)
- **Конкретный существующий пир** (созданный до установки памяти или с дрейфом поверхностей) — подключается той же командой вручную: `iapeer-memory provision-peer --cwd <папка-пира> --runtime claude|codex --personality <имя>`.
- **Все пиры разом** — `iapeer-memory verify --repair` (или повторный идемпотентный `iapeer-memory init`) проходит по всем пирам и переустанавливает поверхности.

`iapeer-memory init` ставит саму систему памяти (демон, поиск, кураторов, слот), а пиров не создаёт — это делает iapeer. Что именно пир получает в поверхностях и в чём паритет claude и codex — в [10 — Интеграция](10-интеграция.md).

После подключения агент при следующем запуске получит в системном промпте карту своей памяти и инструмент `memory_search`.

## Первая заметка и поиск

**Личная заметка (оперативка).** Агент пишет прямо в свою папку оперативки `06_Оперативка_агентов/<своё-имя>/` (или `06_Agent_Memory/<имя>/` в английской раскладке). Достаточно тела и двух полей — остальное проставит система:

```markdown
---
subtype: грабли
description: «После обновления плагина нужен перезапуск MCP-процесса»
---
Живой MCP держит старый код в памяти; обновление на диске не подхватывается,
пока процесс не перезапустишь.
```

**Заметка в канон.** То, что полезно всей команде, агент пишет напрямую в нужную папку канона по жанру — `01_Знания/` для факта, `02_Решения/` для выбора и т. д. (или английские `01_Knowledge`, `02_Decisions`). Папка объявляет жанр, а хук записи проставляет служебные поля (тип по папке, автор, статус, заголовок, отметки) прямо при записи — без модели. Достаточно написать самодостаточный текст; раскладывать черновики и стадировать ничего не нужно. Курирование позже вычитает и обогатит связями ([08 — Курирование](08-курирование.md)).

**Поиск.** Из сессии агента — инструментом `memory_search`:

```text
memory_search("перезапуск MCP после обновления плагина")
→ список заметок с путями, типом, фрагментом и оценкой релевантности
```

Поиск идёт по всему хранилищу команды, не только по своим заметкам. Найдя путь, агент читает заметку обычным чтением файла.
