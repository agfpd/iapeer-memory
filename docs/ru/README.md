# iapeer-memory

**Русский** · [English](../README.md)

iapeer-memory — общая память команды агентов. Это хранилище, куда участники команды складывают знания и куда обращаются за ними: один агент записал решение или вывод — другой найдёт его поиском. Память переживает перезапуски сессий и сжатие контекста, поэтому команда не теряет накопленное между разговорами.

Память делится на две части:

- **Канон** — общее знание команды: знания, решения, идеи, проекты, списки. Сюда попадает то, что полезно всем и надолго.
- **Оперативка** — личные заметки каждого агента: обратная связь, рабочий контекст, профиль владельца, грабли. Своя у каждого, читать может вся команда.

Хранилище (vault) — это обычные markdown-файлы, совместимые с Obsidian. Поиск, индексация и доставка в контекст работают поверх них через демон `memoryd`.

```text
   агент пишет                                агент ищет
   заметку в vault                            memory_search("…")
        │                                          │
        ▼                                          ▼
   ┌──────────────────────────────────────────────────────┐
   │  memoryd — индексация · поиск · доставка в контекст     │
   │  единый демон, владелец базы и поиска                  │
   └──────────────────────────────────────────────────────┘
        │                                          │
        ▼                                          ▼
   кураторы (по такту)                        слой 5 промпта:
   связи · здоровье · консолидация            карта заметок агента
```

iapeer-memory — эталонный провайдер слота памяти [iapeer](https://github.com/agfpd/iapeer): он занимает единственный на хост слот памяти и подключается к команде агентов через её механизмы (системный промпт, обмен сообщениями, расписания).

## Что это даёт

- **Общая на всю команду.** Вывод, сделанный одним агентом, доступен остальным — без пересказа и копирования между сессиями.
- **Переживает перезапуск и сжатие.** Заметка сохраняется между сессиями; агенту в новой сессии достаётся карта его памяти прямо в системном промпте.
- **Достаётся поиском, а не свалкой.** `memory_search` находит по смыслу и содержанию; курирование держит хранилище в порядке — обогащает связи, чинит структуру, сводит дубли. Устаревшее уходит в архив само, по статусу.
- **Курируется автоматически.** Кураторы (Index, Scriber, DreamWeaver) поднимаются по такту и обогащают связи, вычитывают канон и консолидируют личные заметки; между тактами их нет — постоянен только демон.

## Быстрый старт

Требуются уже установленные и работающие [iapeer](https://github.com/agfpd/iapeer) и `notifier-runtime`.

```bash
# Установить и развернуть: vault, демон, кураторы, слот памяти
npx @agfpd/iapeer-memory init
```

Команда спросит путь к хранилищу, язык (русская или английская раскладка папок) и пр., затем создаст всё необходимое. Подробно — в [02 — Быстрый старт](02-быстрый-старт.md).

## Статус

Распространяется одним npm-пакетом `@agfpd/iapeer-memory` — пакет и есть вся система целиком (демон, поиск, кураторы); подключение сессии агента к памяти идёт прямыми per-peer поверхностями. Поиск работает на BM25 из коробки; векторный поиск и переранжирование подключаются опционально. Платформа — macOS, как и у iapeer.
